Порядок работы строго по §4 скилла:

2. Прогони `pipeline/build_data.py`, прочитай `data.json`: числа, метки, доли этапов, кому нужен разбор «ниже среднего».
3. Прочитай резюме всех разобранных сделок и транскрипты тех, на которые будешь ссылаться. Выпиши дословные цитаты: сильные приёмы и места потери сделки. Цитаты с темами стоп-листа §9 не бери.
4. Определи записи контакт-центра по §7.2, перечисли их номера в `contact_center_calls`. В тексте отчёта про них не пиши ни слова.

Требования к языку — §3: клиенты вместо лидов, выручка вместо денег, среднее по группе вместо базы. Запрещены транзакционная, дуга, скоринг, кластер, инверсия, критический кейс, латиница вне названий продуктов. Каждый пункт — законченное предложение с подлежащим и сказуемым. Конструкция вывода: наблюдение → следствие для выручки → управленческое действие.

Что учесть по окружению:
- у git в этой машине не задано имя автора, коммить так: `git -c user.name="AxsaTerenta" -c user.email="fawnsgbrosz6k72@outlook.com" commit`;
- файл `eduson-design-book/eduson-logo.png` внутри WebP, поэтому логотип встраивается в страницу как данные — это делает `render_html.py`, менять не нужно;
- репозиторий приватный, страница отдаётся GitHub Pages по адресу `https://axsaterenta.github.io/Claude-test/reports/{период}/`, обновляется в течение минуты после push;
- если в `main` прилетели чужие коммиты, делай `git rebase origin/main`, не перезаписывай чужую работу.

В конце пришли: ссылку на страницу, объём выборки, метки менеджеров, список системных паттернов с числом сделок, перечень тех, кому собран разбор «ниже среднего».

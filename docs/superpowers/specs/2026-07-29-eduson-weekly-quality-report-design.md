# Дизайн: скилл `eduson-weekly-quality-report`

Дата: 2026-07-29
Статус: реализован и проверен на неделе 20–26 июля 2026 года (команда Анара)
Основание: обратная связь руководителя группы по отчёту от 13.07.2026, устные правки заказчика 29.07.2026, замечания по первому прогону нового отчёта 29.07.2026

## 1. Задача

Недельный отчёт по качеству был оторван от выручки: он оценивал речевые модули без связи с продажами, обобщал единичные наблюдения на группу, подсвечивал несуществующие риски и читался сплошным текстом. Отдельная проблема — воспроизводимость: в новом чате отчёт получался другим по составу, языку и оформлению.

Цель: пересобрать отчёт так, чтобы каждый вывод о качестве стоял рядом с выручкой, каждое обобщение имело объём выборки, формат читался лицами, принимающими решения, а повторный прогон в другом чате давал тот же документ.

## 2. Границы

Отдельный скилл `eduson-weekly-quality-report` собирает недельный отчёт. Базовый `eduson-deal-review` остаётся методологией разбора одной склеенной сделки; в нём зафиксированы стоп-лист, категории A/B/C и словарь (§−1.5).

## 3. Решения заказчика

| Параметр | Решение |
|---|---|
| План продаж | Плана нет. Сравнение ведётся со средним по группе — строкой «Всего» |
| Порог системного вывода | Строго более 4 сделок, объём выборки печатается всегда |
| Категории сделок | A, B, C и «недостаточно данных»; названия профилей упразднены |
| Критические кейсы | Уровень упразднён, остаются зоны роста |
| Словарь | «клиенты» вместо «лидов», «выручка» вместо «денег», «среднее по группе» вместо «базы»; запрещены транзакционная, дуга, скоринг, кластер, инверсия, латиница |
| Язык | Только законченные предложения; конструкция «наблюдение → следствие → действие» |
| Ядро отчёта | Таблица «результат и качество» плюс разбор причин отставания |
| Оформление | Дизайн-бук Eduson, страница на GitHub Pages |
| Ссылки | Номер сделки ведёт в карточку amoCRM; ссылки на оценку и аудио не публикуются |

## 4. Архитектура

Четыре слоя, каждый — отдельный скрипт в `skills/eduson-weekly-quality-report/pipeline/`:

1. **`build_data.py` — слой данных.** Разбирает выгрузку звонков, отсекает записи контакт-центра, склеивает сделки по номеру, размечает признаки этапов `P1…P9`, присваивает категории A/B/C, считает метрики, метки и профили менеджеров, определяет, кому нужен разбор «ниже среднего». Результат — `data.json`, единственный источник чисел.
2. **`render_report.py` — слой текста.** Собирает `REPORT.md`, `REPORT.json`, `CARDS.json`, `GAP.json` из `data.json` и авторских текстов `content.json` по фиксированным шаблонам.
3. **`render_html.py` + `book_css.py` — слой вёрстки.** Превращает Markdown в страницу дизайн-бука: жёлтый герой, нумерованные разделы, плитки показателей, карточки цитат, строки «ключ — значение», свёрнутые разделы с третьего, кнопка выгрузки плана развития, встроенный логотип.
4. **`verify.py` — слой проверки.** Останавливает публикацию при нарушении словаря, языка, порогов выборки, прослеживаемости, порядка разделов или состава вёрстки.

Модель пишет только `content.json`. Числа, доли, списки сделок и вёрстку она не набирает руками — это и даёт совпадение отчётов между прогонами.

## 6. Правила достоверности

- Единица анализа — склеенная сделка по номеру в amoCRM.
- Записи контакт-центра не считаются нигде и в тексте не упоминаются.
- Менеджер с числом клиентов меньше десяти не интерпретируется.
- Менеджер с выручкой на клиента не ниже среднего по группе −5 % не попадает в отстающие.
- Системный вывод — только при более чем четырёх сделках, с подписью выборки.
- Каждый вывод живёт ровно на одном уровне, повтор заменяется ссылкой на паттерн.
- Объём проверенных записей не используется как довод о качестве потока.

## 7. Критерии приёмки

- [x] У каждого менеджера рядом с баллом стоят клиенты, конверсия, продажи, выручка, средний чек и выручка на клиента.
- [x] Высокорезультативный менеджер не попадает в отстающие без пояснения расхождения.
- [x] Ни один вывод по группе не построен на четырёх и менее сделках.
- [x] Для каждого вывода указан объём выборки цифрами.
- [x] Каждая находка ведёт к сделке и этапу разговора, номер сделки — ссылка в amoCRM.
- [x] При отклонении выручки на клиента более 30 % отчёт объясняет, что относится к потоку, а что к работе менеджера.
- [x] План развития можно переслать сотруднику без правок и выгрузить отдельным файлом.
- [x] В отчёте нет тем стоп-листа, запрещённых слов и незаконченных фраз.
- [x] Повторный прогон конвейера даёт побайтно тот же отчёт.
